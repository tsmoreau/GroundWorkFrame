# Groundwork — Project Setup

## What this project is

A small business backend boilerplate called Groundwork. The first deployment target is Denhaus (denhaus.la), a design studio for outdoor pet environments. The app manages the full lifecycle: lead intake → client conversion → job tracking → invoicing → payment → bookkeeping export.

## What already exists

There is an existing repo (GroundWorkFrame) with a working frontend prototype built as a Next.js app. The prototype lives under `artifacts/groundwork/`. It has:

- Full page structure: public landing, contact form, gallery, admin dashboard, admin CRUD for leads/clients/jobs/invoices, settings page, client-facing invoice page at `/invoice/[token]`
- A `DataProvider` React context with in-memory state backed by localStorage as a stand-in for a real API
- Realistic mock data for Denhaus (leads, clients, jobs, invoices with proper line items and payment methods)
- Types, utils, and enums that match the spec
- A warm/earthy Denhaus color system throughout the UI

### 3. Add the OpenAPI spec as a reference document

Create `docs/openapi.yaml` with the full API specification. This is documentation only — no code generation pipeline, no generated packages. The spec should cover all endpoints:

**Endpoints:**
- `GET/POST /api/leads`, `GET/PATCH /api/leads/:id`, `POST /api/leads/:id/convert`
- `GET/POST /api/clients`, `GET/PATCH /api/clients/:id`
- `GET/POST /api/jobs`, `GET/PATCH /api/jobs/:id`, `POST /api/jobs/:id/invoice`
- `GET /api/invoices`, `GET/PATCH /api/invoices/:id`, `POST /api/invoices/:id/send`, `GET /api/invoices/:id/pdf`, `POST /api/invoices/:id/checkout`
- `GET /api/invoices/token/:token` (public, no auth)
- `POST /api/payments/webhook` (Stripe webhook)
- `POST /api/upload/presign`
- `GET /api/export/quickbooks`
- `GET/PATCH /api/settings`
- `GET /api/gallery`
- `GET /api/dashboard/summary`, `GET /api/dashboard/upcoming-jobs`, `GET /api/dashboard/outstanding-invoices`

**Schemas:** Lead, Client, Job, Invoice, LineItem, Note, Pet, PetInfo, BusinessSettings, GalleryItem, DashboardSummary, InvoicePublicView. Use the types already defined in `lib/types.ts` as the source of truth for field names and enums.

**Key schema rules:**
- `Note` is `{ text: string, createdAt: datetime }` — not a plain string
- No `totalAmount` field on Job or Invoice — it's computed from lineItems at read time
- Invoice has `token`, `sentAt`, `viewedAt`, `paymentMethod`, `paymentReference` fields
- `paymentMethod` enum: `stripe_ach`, `stripe_card`, `zelle`, `check`, `bank_transfer`, `other`
- Photos are GCS object keys (strings), not full URLs
